(1) If a client to server message is dropped, the server never receives the move. The board will remain unchanged and the game will not progress. If a server to client message is dropped, the client never sees the updated board. It may prompt for a move based on outdated info.
(2) Our save/load approach would fail when there are multiple active games or clients because it saves only one file per game ID and doesn't track whch clients are attached. A restart could load an incomplete state. It is also brittle because it writes a raw struct without version or recovery for partial writes. A mid-write failure can corrupt the saved board and make loadgame return incorrectly or fail.
